1. プロダクト概要
--------------------------------------------------------------------------------

1.1 名称
  - 画面・ブラウザタブの表記: 「芝しごと・ターフプール」
  - リポジトリ / パッケージ名: turfpool（英字のプロダクトコードとして併用）

1.2 一言で
  サッカー場の芝の状態を、ピッチ上の「四隅＋中央」の 5 地点の写真から
  把握するためのブラウザアプリ。各写真から複数の植生・画質系指標を算出し、
  5 地点の値をピッチ形状の「プール状」3D ビューで空間的にイメージできる。

1.3 価値提案（誰のどんな課題か）
  - グラウンド全体のムラや角・中央の差を、一枚の俯瞰写真だけではなく、
    定点のクローズアップの集合として捉えたい現場担当者向け。
  - 指標の名前（GCP, ExG, VARI 等）は専門的になりがちなので、画面内で
    「算出ロジック」「値の考え方」「ヒント」を区分して説明している。
  - 画像を外部に送らないため、現場撮影のセンシティブさを下げられる。

1.4 技術的な位置づけ
  - フロントエンドのみ（Vite + React + TypeScript）。
  - 解析は Canvas 2D とピクセル走査。OpenCV.js 等は不使用。
  - 3D は three.js を React Three Fiber 経由で使用。

2. 想定ユーザーと利用シーン
--------------------------------------------------------------------------------

2.1 想定ユーザー
  - 日本のサッカーグラウンドの芝管理に関わる担当者（グリーンキーパー、
    施設管理、外注先の監督者など）。
  - 生育や刈込みのムラを「感覚」だけでなく簡易数値で共有したい場合。

2.2 典型的な利用シーン
  - 試合前後や週次巡回で、決めた 5 地点を毎回同じように撮影し、数値と
    プール表示でトレンドを追う。
  - デモ用のサンプル画像で UI を試したあと、実写真に差し替えて本番比較。

2.3 あえて想定していないこと（限界の明示）
  - 衛星画像やドローンの正射影に基づく正確な GIS 解析ではない。
  - 病害の同定や肥料設計の意思決定まで自動で行うものではない。
  - カメラ・照明・露出が大きく異なる写真同士の絶対比較は誤解を招きやすい。
    同条件・相対比較を推奨する UI コピーを入れている。

3. 画面構成と操作フロー
--------------------------------------------------------------------------------

3.1 ヘッダー
  - タイトル「芝しごと・ターフプール」、バージョン表記、短いプロダクト説明。

3.2 パートナー・関連リンク（TurfPartnerBanners）
  - 芝しごとサイトへのバナー（パートナー募集、ブログ、YouTube 等）。
  - 画像は public/ 配下。アプリのコア機能とは独立。

3.3 メイン上部「この画面の流れ」
  ① ピッチの 5 地点に写真を置く
  → ②「プール状ビュー」で指標のムラや高低を眺める
  という 2 ステップを常時表示し、初見の迷いを減らす。

3.4 ピッチ・アップローダー（PitchUploader）
  - IFAB 国際試合サイズ比（105m × 68m）に合わせた viewBox の SVG で白線を描画。
  - 5 スロット: 左上(tl), 右上(tr), 左下(bl), 右下(br), 中央(c)。
  - 各スロット: ラベル、画像選択（input file）、サムネ、測定指標アコーディオン。
  - 初回はサンプル画像が入り、解析済み。いずれかをユーザー画像に差し替えると
    isSample が false になり、メタ情報が親へ伝わる。
  - 左下・右下はアコーディオンが画面下にはみ出さないよう、パネルを上方向に
    開く（opensAbove）実装。

3.5 プール状ビューへの入り口
  - 5 地点すべて indices が揃うと「プール状ビュー」ボタンが有効。
  - 横に状態メッセージ:
    - 未完了: 解析完了待ち
    - 完了かつ全サンプル: 現場写真への差し替え推奨
    - 完了かつユーザー写真混入: 比較準備完了の肯定メッセージ

3.6 プール状ビュー（PoolVisualization）
  - 指標セレクト（5 種）。
  - Three.js キャンバス（PoolScene）: 床、ピッチライン、水面メッシュ、
    コーナー Z 目盛り、操作は OrbitControls。
  - 右側に色凡例（PoolHeatLegend）。
  - 下部に指標ガイド（PoolMetricGuidePanel）: 算出ロジック / 値の考え方 / ヒント。

3.7 フッター
  - グロウアンドプログレス（芝しごと）サイトへのリンク。

4. 画像入力と解析パイプライン
--------------------------------------------------------------------------------

4.1 入力
  - 各スロットで image/* を選択。createImageBitmap でデコード。

4.2 前処理（fileToAnalysisCanvas / imagePipeline.ts）
  - 長辺が ANALYSIS_MAX_EDGE_PX（既定 768px）を超えないよう等比縮小。
  - Canvas に描画し、その canvas を indices 計算へ渡す。
  - 目的: メインスレッド負荷とメモリの抑制。画素数に比例してループコストが増える。

4.3 解析本体（analyzeTurfImage / indices.ts）
  - getImageData で RGBA を取得し、全画素を 1 パスで走査。
  - 同一ループ内で GCP 用 HSV、ExG 和、VARI 和、芝マスク上の G の二乗和、
    グレースケール（Sobel 用）を累積。
  - グレースケールは BT.601 係数: 0.299R + 0.587G + 0.114B。
  - Sobel は内側画素のみ（1..w-2, 1..h-2）で勾配ベクトルの大きさを平均。

4.4 エラー
  - Canvas が取れない、幅・高さが 2 未満、などは Error を投げ UI に表示。

5. 指標の定義（数式と実装の対応）
--------------------------------------------------------------------------------
  以下の閾値は src/config/turfConstants.ts に集約。変更時は UI 説明との整合を確認。

5.1 GCP（%）緑の被覆率
  - 各画素の RGB を OpenCV 8bit HSV に近い形へ変換（H: 0–179, S,V: 0–255）。
  - 芝とみなす範囲（既定）:
      H ∈ [35, 90], S ∈ [40, 255], V ∈ [40, 255]
  - GCP = (芝画素数 / 全画素数) × 100
  - 解釈: フレーム内に「芝らしい色」がどれだけ占めるか。土・白線・観客が
    多いと低下しやすい。撮影の切り取りに強く依存。

5.2 ExG（芝緑度）
  - 画素ごとに R,G,B を 0–1 に正規化した R',G',B' について
      2G' − R' − B'
    を全画素で平均。
  - Woebbecke 系の Excess Green の考え方に沿う簡易実装。
  - 正で大きいほど緑チャンネル優勢。露出・ホワイトバランスの影響を受ける。

5.3 VARI（芝活力度）
  - 分母 |G' + R' − B'| ≥ VARI_DENOM_EPS（既定 0.02）の画素のみ対象。
  - 各対象画素で (G' − R') / (G' + R' − B') を足し、画素数で平均。
  - Gitelson の VARI に近い形。土の影響を抑えやすいが、撮影条件の差は残る。
  - 絶対閾値の「安全・危険」より、ExG との相対読みを推奨。

5.4 Color Uniformity（0–100）色均一性
  - 芝マスク（GCP と同じ HSV 条件）内の G チャンネルについて標準偏差 σ_G。
  - 芝画素が 0 のときは全画素の G で同様に σ_G を計算。
  - score = clip(1 − σ_G / UNIFORMITY_STD_SCALE, 0, 1) × 100
    既定 UNIFORMITY_STD_SCALE = 88（0–255 スケールの σ_G）。
  - 高いほど均一。サッカー場の縞・刈り差をある程度許容するよう分母を大きめ。

5.5 Texture Quality（0–100）刈込芝面品質
  - グレースケールに Sobel。勾配強度 ‖∇I‖ の平均を meanMag。
  - score = clip(exp(−meanMag / TEXTURE_SOBEL_DECAY_REF), 0, 1) × 100
    既定 TEXTURE_SOBEL_DECAY_REF = 292。
  - 高いほど微細な明暗変化が少なく滑らか。低いと粗さ・刈り目が目立つ。
  - 指標が textureQuality のときのみ、水面 Z に微細なジッターを付加（視覚的な
    粗さ表現）。他指標は滑らかな水面のみ。

6. プール状ビュー（3D）の仕様
--------------------------------------------------------------------------------

6.1 コンセプト
  - ピッチを「水が張ったプール」のように見立て、選択指標の相対的な高低を
    水面の高さと色（ヒートマップ）で表現する。

6.2 平面と分割
  - PlaneGeometry。アスペクトは UI ピッチと同じ 105:68 に対応する世界座標
    POOL_PLANE_W × POOL_PLANE_H（既定 3.2 × 2）。
  - 分割: POOL_PLANE_SEGMENTS_X × POOL_PLANE_SEGMENTS_Y（既定 40×28）。

6.3 5 地点の値から面全体への補間（interpolate.ts）
  - UV 平面上に tl(0,0), tr(1,0), br(1,1), bl(0,1), c(0.5,0.5) を置き、
    4 三角形（各々 tl–tr–c 等）に分割し、各三角形内で重心座標により線形補間。
  - 各頂点の生の指標値は、その地点の写真から算出されたスカラー。

6.4 正規化と色
  - 5 地点の当該指標の最小 minV・最大 maxV を取り、各頂点の raw を
    min–max 正規化（同一分母でプール全体を比較）。
  - poolTheme のヒート色へマッピング。凡例も同じ min/max。

6.5 メッシュの Z と UV の v 方向
  - 水面 Z = POOL_WATER_SURFACE_BASE + norm × POOL_METRIC_DEPTH_AMPLITUDE
    （既定振幅 0.4）。
  - Three.js PlaneGeometry のローカル +Y は画面上方に対応しやすい一方、
    補間側の v は「画像座標」で上が v=0。頂点の v を
      v = 1 − (ly / POOL_PLANE_H + 0.5)
    とし、四隅ラベルとプール表示の対応を一致させている。

6.6 目盛り（PoolDepthRulers3D）
  - 四隅に縦スパインと十字目盛り。表示値は min・(min+max)/2・max に対応する
    Z（norm=0, 0.5, 1 の水面モデル）。
  - Line は depthTest false かつ高い renderOrder。ラベルは Html ではなく
    troika Text + Billboard で、透視によるズレを避ける。

6.7 操作
  - OrbitControls: ズーム・回転。極角に上限があり、真下からの裏返しを抑制。

6.8 パフォーマンス
  - WebGL。DPR は Canvas で上限付き。モバイルでも動く想定だが重い端末では
    セグメント数や DPR を下げるチューニング余地あり。

7. UI テキストと初学者向けガイド
--------------------------------------------------------------------------------

7.1 ピッチ上バナー（全地点サンプル時のみ）
  - 各地点をタップして現場写真へ差し替えるよう促す。サンプルのままでも
    プールは試せる旨を併記。

7.2 指標ガイド（PoolMetricGuidePanel）
  - 指標ごとに 3 枠: 算出ロジック（式・閾値） / 値の考え方（目安） / ヒント。
  - 定数は turfConstants と揃えて記述。

7.3 表示フォーマット（format.ts）
  - 指標値の小数表示ルール（|値|≥1 なら小数 1 桁、未満なら 2 桁等）。


--------------------------------------------------------------------------------
8. プライバシーとセキュリティ
--------------------------------------------------------------------------------

8.1 データの扱い
  - 解析はブラウザ内完結。fetch で画像をアップロードする処理はない。
  - プレビュー用 object URL は blob: を revoke してリークを抑止。

8.2 注意喚起
  - EXIF の位置情報などは「アプリが送信しない」こととは別に、端末内に
    残る範囲ではユーザーの責任で管理される。公開記事で触れると親切。

11. ブログ記事・解説動画で使える章立て（提案）
--------------------------------------------------------------------------------

  A. 課題: 俯瞰一枚ではムラが見えにくい／数値の共有が難しい

  D. 実運用: 撮影条件を揃える、同じ地点を踏む
  E. 指標を 1 つずつ噛み砕く（GCP → ExG → …）
  F. プールの見方（色・高さ・四隅と中央の対応）
  G. プライバシー（ブラウザ内完結）と限界（絶対評価ではない）
  H. 技術メモ（任意）: Vite, React, three.js, クライアント解析

12. 用語ミニ辞典（動画台本向け短文化）
--------------------------------------------------------------------------------

  GCP … 画面上の芝らしい色の画素の割合（%）。フレーム構成に依存。
  ExG … 緑が RGB の中でどれだけ強いかの平均的な指標。
  VARI … 緑と赤青の関係を分母正規化した植被指標系。ExG と併用で解釈補助。
  Color Uniformity … 緑チャンネルのばらつきの少なさを 0–100 で表すスコア。
  Texture Quality … 微細な明暗の変化（Sobel）が少ないほど高いスコア。
  プール状ビュー … 5 地点の値をピッチ上に補間し、水面の色と高さで見せる 3D。
